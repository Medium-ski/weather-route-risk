# 分析与决策逻辑

本文记录分析和决策的实际实现；界面和报告将在第四步接入。

## 路线和采样

路线几何、里程和耗时由 OSRM 返回；离线使用其已保存响应。以 `config/assumptions.yaml` 中的间距为默认值沿各段几何采样，保留每段起终点；各段使用各自的真实路由里程和耗时，段内按几何距离比例推算里程和经过时间。分段的独立吸附点不一致时保留两侧坐标，不添加连接道路。

## 时空对齐

所有时间计算使用 UTC。每个采样点的经过时间为发车时间加累计分段耗时，四舍五入到最近整点，半小时恰好进位。离线快照仅覆盖 2025-01-01 至 2025-01-02 UTC；不在范围内时报错，不复用错误时刻的数据。天气接口请求速度单位 m/s。

## 风险等级

等级 0、1、2、3、4 分别为无阈值命中、蓝、黄、橙、红。阈值与天气码映射见 `config/thresholds.yaml`，风险取各已知要素中的最高级。相邻区间共用边界时取较高等级；任务书中红色注明“大于”的降水及风速上限分别严格采用 >16 mm/h 和 >17.2 m/s。低温伴降水的分界为低于 -2℃ 红、-2℃ 至不足 0℃ 橙、0℃ 至 2℃ 黄。

能见度缺失且天气码为雾时，按阈值文件中的明确假设推断，并标注“推断”；其他情况保持缺失。未知天气码或无法推断能见度时标记结果不完整，不把未知当作安全。以上等级是本原型规则推断，不是气象部门发布的官方预警。

## 场景

场景 YAML 的 E1、E2 等表示沿采样点顺序的区间；只有区间经过时间与事件时间窗重叠才标注事件。所有事件始终标为模拟；只有 `confirmed: true` 才可在模拟场景中表示已确认。慢行比例表示剩余速度比例。决策比较时，以原计划发车时间作为事件时间窗零点，按事件起止时刻分段更新通过时间，再重新匹配天气。可选 route_id 将事件限定在指定路线；未指定时作用于各路线同编号区间。区间与事件时间窗采用左闭右开。确认封路不可通行；未确认封路只作为模拟风险，不称为现实确认封路。

## 成本和排序

- 对每条路线计算相对原计划发车时间 -3、-2、-1、0 小时的方案。早于参考时间、遇到模拟已确认封路或无法获得有效天气的方案不可推荐。
- 里程成本 = 真实路由里程 × 模拟运价；运输时间成本 = 经过场景调整的预计时长 × 模拟小时成本；仓储成本 = 输入仓储时长 × 模拟仓储费。没有提供仓储时长时默认零。
- 延误概率是按最高天气风险等级查表的模拟假设；若模拟预报封路，使用表值和封路概率下限的较大者。预计到达晚于原计划发车时刻加承诺时效时，按已知超时将概率设为 1。延误成本为概率乘模拟赔付。
- 风险惩罚 = 模拟等级惩罚 × 货类系数；存在模拟预报封路时再加对应模拟惩罚。
- 加权预期成本 = （偏好底数 + 省钱偏好）×（里程成本 + 仓储成本 + 预期延误成本）+（偏好底数 + 赶时间偏好）× 时间成本 + 风险惩罚。两个偏好的取值为 0 到 1；底数和所有参数见 `config/assumptions.yaml`。这是用于排序的模拟指标，不是实际运费报价，也不应跨不同权重直接比较。
- 在当前所有可行路线和发车时间中找最差成本，按任务书计算推荐指数 = 100 ×（1 − 此方案成本 ÷ 最差成本）。最差成本为零时，全部并列计 100；其他成本完全相同的情况按原公式均为 0。数值越高仅表示在当前候选集和参数下的相对排序。
- 每条路线保留成本最低的可行发车时间；成本相同时优先不改变计划。自动决策选成本最低的路线，输出三条理由与需要重新比较的触发条件。

场景 `preference_comparison.yaml` 为 A 路线注入明确标注的模拟减速，供测试偏好变化；不会将减速描述为真实路况。所有模拟概率均非经过验证的统计预测。
